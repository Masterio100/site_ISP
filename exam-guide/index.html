Тема проверочной системы в образце КИМ — продажа обуви: каталог, заказ, роли Клиент / Менеджер / Администратор. В вашем варианте предметная область, поля и «ключевой параметр» могут отличаться — структура и требования задания остаются теми же.

Обзор и регламент

Что оценивается

Только готовый продукт, а не процесс: рабочая база данных, приложение, интерфейс, файлы в репозитории. Но эксперты смотрят и «как сделано»: структуру проекта, читаемость кода, обработку исключений, корректность SQL и транзакций.

Аттестация: ПА — задания 1–2; ГИА ДЭ БУ (базовый уровень) — задания 1–4. Профильный уровень добавляет вариативную часть (ещё 25 баллов, итого 100), её содержание определяет образовательная организация.

До начала

  • Допуск по документу, удостоверяющему личность; рабочие места распределяют жеребьёвкой.
  • Инструктаж по технике безопасности — под подпись.
  • Не менее 15 минут на ознакомление с заданием — они не входят в время экзамена.
  • Вопросы эксперту — только по трактовке формулировок, не по решению. Ответ получают все одинаково и он фиксируется в журнале.
  • Проверьте среду: IDE, СУБД, клиент БД, Git, доступ в репозиторий.

Интернет

  • Доступ только в зоне общего пользования, ≤ 15 минут за выход, без авторизации на сайтах; время идёт из времени экзамена.
  • Только справочная информация.
  • Нельзя: сетевые диски, мессенджеры, генеративные ИИ, репозитории с кодом, сайты вопросов-ответов для программистов, соцсети.
  • Компьютер контролируют удалённо.

Число выходов в документах отличается: в КИМ — «не более 15 минут», в методичках — 1 раз для ПА и 2 раза для ГИА ДЭ БУ. Уточните у администратора центра проведения экзамена.

Во время экзамена

  • Администратор объявляет время каждые 60 минут, а также за 30 и 5 минут до конца.
  • Останавливать работу по истечении времени отдельного задания не требуется — важен общий лимит.
  • Сбой оборудования — прекратить работу и сообщить эксперту: время простоя компенсируют.
  • Запрещено: подключать и отключать кабели, вскрывать оборудование, использовать внешние носители.
  • Результаты загружаются в репозиторий по ходу выполнения каждого задания.

Баллы

Критерий оценивания совпадает с наименованием профессиональной (ПК) или общей (ОК) компетенции. Подробные шкалы по подкритериям в этих документах не приведены — ниже распределение по компетенциям из спецификации.

ПА — 25 баллов

ГИА ДЭ БУ — 75 баллов

Что из этого следует. База данных и код — 25 баллов из 75 (треть), и столько же весит сопровождение (задание 3) и интеграция (задание 4). Больше всего баллов (12) приносит разработка объектов БД по анализу предметной области — то есть правильные таблицы, ключи и 3НФ. Ошибки здесь тянут за собой все остальные задания.

Эксперты проверяют ключевые критерии минимум вдвоём: расчёт скидки, подсветку, заглушку картинки. Каждый выставленный балл сопровождается пометкой, за что именно.

    Шаблон README.md

    Нужно описание реализованных возможностей без общих фраз.

    # ООО «НазваниеКомпании» — система заказа обуви

## Что умеет система
- Вход по логину (без пароля); ФИО пользователя в правом верхнем углу.
- Каталог: изображение (или picture.png), категория, наименование,
  производитель, состав, цена со скидкой, остаток «много/мало».
- Скидка 25% на товары без заказов в прошлом календарном месяце.
- Подсветка карточек с остатком ≤ 3.
- Поиск по наименованию и описанию, фильтр по категории,
  сортировка по цене — в реальном времени и совместно.
- Оформление заказа: размер, количество, подтверждение с датой,
  отказ на любом этапе; остатки пересчитываются.
- Менеджер: список заказов, добавление, удаление, состав заказа.
- Администратор: то же + изменение даты и удаление позиций.

## Состав репозитория
- src/ — исходный код
- db/ — скрипт БД (структура и данные), ER-диаграмма (PDF)
- bin/ — исполняемые файлы

## Запуск
1. Выполнить db/script.sql в PostgreSQL.
2. Указать строку подключения в config.
3. Запустить приложение.
    Исходный код загружается структурой файлов, а не архивом. Для 1С вместо скрипта БД сохраняется файл конфигурации с данными .dt. Загружайте результаты после каждого задания, а не в последние минуты.
