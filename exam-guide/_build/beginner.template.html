Курс «с нуля»

Как сдать демонстрационный экзамен, если вы ни разу не программировали

Здесь всё объяснено простыми словами и по шагам: что поставить на компьютер, что такое база данных, как написать программу и куда её сдать. В конце вы получите работающий учебный проект — по нему можно потренироваться и разобрать каждую строчку.

Честно о сроках. За один вечер программировать не научиться. Но экзамен проверяет вполне конкретный набор умений, и их можно натренировать за 3–4 недели ежедневных занятий по 1–2 часа. Идите по урокам по порядку, ничего не пропускайте и каждое задание делайте руками, а не просто читайте.
Важно про учебный проект. Это тренировочный пример на основе образца из КИМ (магазин обуви). На экзамене вы получите свою предметную область, свои таблицы, макет и стиль. Не заучивайте код — разберитесь, как он устроен, и вы сможете сделать то же самое для любой предметной области.

Урок 0. С чего начать и как учиться

Демонстрационный экзамен (ДЭ) — это не тест с вопросами. Вам дают задание, как на настоящей работе, и вы за отведённое время делаете из него готовый продукт: базу данных и программу. Проверяют результат: открывают вашу программу и смотрят, что она умеет.

Что нужно уметь (всего пять навыков)

  1. Спроектировать базу данных — разложить информацию по таблицам и связать их (урок 4–5).
  2. Загрузить в неё данные из файлов Excel (урок 5).
  3. Написать программу с окнами, которая показывает данные из базы (уроки 6–7).
  4. Реализовать правила: скидка, подсветка, поиск, сортировка, заказ (уроки 7–9).
  5. Сдать работу в репозиторий Git (урок 10).

Как правильно учиться

  • Печатайте код сами. Копировать — быстро, но руки ничего не запоминают. Хотя бы первые два раза перепишите код вручную.
  • Ломайте и чините. Измените число, удалите строку — посмотрите, какая ошибка появится. Это лучший способ понять код.
  • Не бойтесь красных сообщений. Ошибка — это подсказка, а не приговор. Урок 11 учит их читать.
  • Таймер. Начиная со второй недели решайте задания на время — на странице гайда есть таймер.

Запускаем учебный проект — 6 шагов

  1. Создайте базу. Откройте pgAdmin, введите пароль. Слева раскройте «Servers → PostgreSQL». Правая кнопка на «Databases» → «Create → Database…». Имя: shoe_store. Нажмите «Save».
  2. Создайте таблицы. Правая кнопка на shoe_store → «Query Tool». Откройте файл example/sql/schema.sql, скопируйте всё, вставьте в окно запроса и нажмите F5 (или кнопку ▶). Внизу должно появиться «Query returned successfully».
  3. Загрузите данные. Очистите окно запроса, вставьте содержимое example/sql/sample_data.sql, F5.
  4. Укажите пароль в программе. Откройте example/app/config.py и в DB_SETTINGS впишите свой пароль от PostgreSQL.
  5. Запустите. В терминале:

  6. Войдите. Логины для проверки: client1 (клиент), manager1 (менеджер), admin1 (администратор). Пароль не нужен.
Если программа не открылась или выдала ошибку — не паникуйте. Смотрите урок 11: там разобраны самые частые причины (неверный пароль, база не создана, не поставлена библиотека).

Урок 3. Основы Python — ровно то, что нужно для экзамена

Создайте в VS Code файл practice.py и запускайте его командой python practice.py. Пробуйте каждый пример сами.

3.1. Переменные и вывод на экран

product_name = "Кроссовки"
price = 4500
print(product_name)
print("Цена:", price)

Знак = здесь значит «положи в коробку», а не «равно». Слова product_name и price придумываем мы — это имена. Правило из экзамена: имена должны объяснять, что внутри (price, а не x), и писаться в одном стиле: на Python — snake_case (слова строчными через подчёркивание).

3.2. Числа, текст, да/нет

quantity = 3            # целое число
price = 4500.50         # число с дробной частью
name = "Ботинки"        # текст в кавычках
has_discount = True     # да (True) или нет (False)
total = price * quantity
print(total)

Всё после # — комментарий. Компьютер его пропускает; он нужен людям. На экзамене комментарии нужны только к неочевидному: не пишите # умножаем рядом с *.

3.3. Условия: if

total_quantity = 4

if total_quantity > 5:
    label = "много"
else:
    label = "мало"

print(label)

Отступ в 4 пробела обязателен: по нему Python понимает, что относится к if. Сравнения: > больше, < меньше, >= не меньше, <= не больше, == равно, != не равно. Обратите внимание: «если больше пяти — много», а «пять или менее — мало». Именно так в задании: 5 — это ещё «мало».

Можно объединять: and (и), or (или), not (не).

3.4. Списки и циклы

prices = [4500, 8900, 1900]

for price in prices:
    print(price)

print(len(prices))      # сколько элементов
prices.append(6200)     # добавить в конец

Цикл for берёт элементы списка по одному и выполняет вложенный блок для каждого. Каталог товаров в программе — это как раз список, и мы идём по нему циклом, чтобы нарисовать каждую карточку.

3.5. Словари — «карточки» с полями

product = {
    "product_name": "Кроссовки Runner",
    "price": 4500,
    "category_name": "Кроссовки",
}

print(product["product_name"])
product["price"] = 4000

Один товар из базы приходит в программу именно как словарь: по названию поля получаем значение.

3.6. Функции

def stock_label(total_quantity):
    if total_quantity > 5:
        return "много"
    return "мало"

print(stock_label(12))   # много
print(stock_label(5))    # мало

def объявляет функцию. В скобках — то, что ей передают (аргументы). return — то, что она возвращает. Хорошая функция делает одно дело и называется глаголом: calc_final_price, stock_label.

Задание для самопроверки: напишите функцию calc_final_price(price, has_discount), которая возвращает цену, уменьшенную на 25%, если has_discount равно True, иначе — прежнюю цену. Сверьтесь с файлом rules.py ниже.

3.7. Обработка ошибок: try / except

text = "abc"

try:
    quantity = int(text)
except ValueError:
    print("Введите число")

Если внутри try случится ошибка, программа не упадёт, а выполнит блок except. Так мы защищаем приложение: на экзамене проверяют, что программа не закрывается аварийно при неправильном вводе или недоступной базе.

3.8. Импорты и несколько файлов

import rules                      # подключили файл rules.py
print(rules.stock_label(7))       # вызвали функцию из него

from decimal import Decimal       # взяли одну вещь из стандартной библиотеки

Большую программу делят на файлы по смыслу: правила — в rules.py, работа с базой — в database.py, окна — в *_page.py. Так и проверяющему понятнее, и вам проще искать ошибки.

3.9. Деньги: почему Decimal

Обычные дробные числа считают с мелкими неточностями (0.1 + 0.2 даёт 0.30000000000000004). Для денег используют Decimal: Decimal("4500.00") * Decimal("0.75") даёт ровно 3375.0000. База PostgreSQL отдаёт цены типом Decimal — и если умножить его на обычное дробное число 0.75, Python выдаст ошибку. Поэтому в учебном коде скидка записана как Decimal("0.25").

  2. Сделайте словарь товара и функцию, которая принимает его и возвращает строку "Название — цена ₽".
  3. Запросите у пользователя число через input() и обработайте ошибку, если ввели не число.

Урок 4. Базы данных и SQL с нуля

4.1. Зачем таблицы, если есть один большой Excel?

Представьте, что мы записываем заказы в одну таблицу:

ДатаКлиентТоварКатегорияПроизводительРазмер
01.10Иванов И.И.Кроссовки RunnerКроссовкиNord Steps42
01.10Иванов И.И.Ботинки TrailБотинкиАльпина43
05.10Петрова М.С.Кроссовки RunnerКроссовкиNord Steps41

Проблемы: «Кроссовки Runner» и «Nord Steps» повторяются; если производитель переименуется, править придётся везде; опечатка («Кросовки») создаст «новую» категорию. Решение: каждую сущность хранить один раз в своей таблице, а в остальных местах ссылаться на неё по номеру.

4.2. Ключи и связи

  • Первичный ключ (PK) — уникальный номер строки. В таблице category это category_id.
  • Внешний ключ (FK) — поле-ссылка. В таблице product поле category_id указывает на строку в category.
  • СУБД следит за этим: она не даст создать товар с несуществующей категорией. Это и есть ссылочная целостность.
category (category_id PK, category_name)
     │ 1
     │
     ▼ много
product (product_id PK, product_name, price, category_id FK, manufacturer_id FK)
     │ 1
     ▼ много
product_size (product_id PK+FK, size_value PK, quantity)
     │ 1
     ▼ много
order_item (order_id PK+FK, product_id PK+FK, size_value PK+FK, quantity)
     ▲ много
     │ 1
customer_order (order_id PK, order_date, customer_id FK → app_user)

4.3. Третья нормальная форма простыми словами

Задание требует 3НФ. Это три правила:

  1. 1НФ — в ячейке одно значение. Плохо: в поле «Размеры» записано «41, 42, 43». Хорошо: отдельная строка на каждый размер.
  2. 2НФ — каждое поле зависит от всего ключа. Если ключ составной (товар + размер), то в этой таблице нельзя хранить название товара: оно зависит только от товара. Название хранится в product, а в product_size — только остаток.
  3. 3НФ — поля зависят от ключа, а не друг от друга. Плохо: в таблице app_user хранить и role_id, и текст «Администратор» — текст зависит от роли, а не от пользователя. Хорошо: роль в своей таблице role, у пользователя только role_id.
Быстрая проверка: если одно и то же слово (категория, производитель, роль, статус) в таблице повторяется много раз — вынесите его в справочник.

4.4. Имена таблиц и полей

  • Один стиль на всю базу: snake_case (маленькие буквы, слова через _).
  • Имя понятно без пояснений: manufacturer_name, а не mn.
  • Ключ — таблица_id: product_id, order_id.
  • Не смешивайте стили (OrderDate рядом с order_date) — это типичная потеря баллов.

4.5. Основные команды SQL

SQL читается почти как английский. Вводить команды можно в pgAdmin → Query Tool. В конце команды ставится ;.

Показать данные — SELECT

SELECT * FROM product;                        -- все столбцы, все строки
SELECT product_name, price FROM product;      -- только нужные столбцы
SELECT * FROM product WHERE price > 5000;     -- с условием
SELECT * FROM product ORDER BY price DESC;    -- сортировка по убыванию
SELECT * FROM product WHERE product_name ILIKE '%кросс%';  -- поиск, регистр не важен

Объединить таблицы — JOIN. Вместо номера категории хотим видеть её название:

SELECT p.product_name, c.category_name
FROM product p
JOIN category c ON c.category_id = p.category_id;

p и c — короткие псевдонимы таблиц. ON говорит, по какому полю связать.

Посчитать — SUM, COUNT, GROUP BY. Сколько всего пар каждой модели:

SELECT p.product_name, SUM(ps.quantity) AS total_quantity
FROM product p
LEFT JOIN product_size ps ON ps.product_id = p.product_id
GROUP BY p.product_id;

GROUP BY склеивает строки одной модели, SUM складывает остатки по размерам. LEFT JOIN оставляет и те модели, у которых размеров ещё нет.

Добавить — INSERT, изменить — UPDATE, удалить — DELETE

INSERT INTO category (category_name) VALUES ('Тапочки');
UPDATE product SET price = 4000 WHERE product_id = 1;
DELETE FROM category WHERE category_name = 'Тапочки';
Никогда не забывайте WHERE в UPDATE и DELETE: без него изменится или удалится всё в таблице.

«Есть ли заказы в прошлом месяце» — NOT EXISTS. Именно такая проверка нужна для скидки:

SELECT p.product_name,
       NOT EXISTS (
           SELECT 1
           FROM order_item oi
           JOIN customer_order o ON o.order_id = oi.order_id
           WHERE oi.product_id = p.product_id
             AND o.order_date >= date_trunc('month', CURRENT_DATE) - INTERVAL '1 month'
             AND o.order_date <  date_trunc('month', CURRENT_DATE)
       ) AS has_discount
FROM product p;

Разбор: date_trunc('month', CURRENT_DATE) — первое число текущего месяца. Минус один месяц — первое число прошлого. Заказ попадает в «прошлый месяц», если его дата не раньше первого числа прошлого месяца и строго раньше первого числа текущего. EXISTS спрашивает «есть ли хоть одна такая строка»; NOT EXISTS — «нет ни одной». Если заказов не было — has_discount равно true.

Параметры в коде мы подставляем через %s, а не склеиваем строки: так программу нельзя «взломать» через поле ввода (это называется SQL-инъекция).

CREATE TABLE product_size (                       -- создать таблицу
    product_id  INTEGER NOT NULL,                  -- целое число, пустым быть не может

Шаг 3. Загружаем данные из Excel

Заказчик даёт файлы .xlsx с пометкой «import». Данные в них не идеальны: лишние пробелы, дубли, запятая вместо точки, названия вместо номеров. Поэтому действуем так:

  1. Посмотрите файлы. Откройте каждый в LibreOffice. Запишите: какие столбцы, сколько строк (последний номер строки минус заголовок), есть ли пустые ячейки и дубли.
  2. Создайте промежуточные таблицы staging_* со всеми полями текстовыми. В них можно загрузить что угодно — не споткнётесь на типах. 
    CREATE TABLE staging_product (
    product_name      TEXT,
    category_name     TEXT,
    manufacturer_name TEXT,
    description       TEXT,
    composition       TEXT,
    price             TEXT,
    image_file        TEXT
);
    (Колонки — пример. Берите те, что в вашем файле, в том же порядке.)
  3. Загрузите файл в staging. Способ А — мастер pgAdmin: сохраните лист как CSV (LibreOffice → «Сохранить как» → «Текст CSV», кодировка UTF-8), затем правая кнопка на таблице → «Import/Export Data…», формат CSV, галочка «Header». Способ Б — скрипт на Python: 
    import openpyxl
import psycopg2

workbook = openpyxl.load_workbook("products_import.xlsx")
sheet = workbook.active

connection = psycopg2.connect(dbname="shoe_store", user="postgres", password="ВАШ_ПАРОЛЬ", host="localhost")
with connection:
    with connection.cursor() as cursor:
        for row in sheet.iter_rows(min_row=2, values_only=True):    # min_row=2 пропускает заголовок
            cursor.execute(
                "INSERT INTO staging_product VALUES (%s, %s, %s, %s, %s, %s, %s)",
                [None if cell is None else str(cell) for cell in row],
            )
connection.close()
    Количество %s должно совпадать с числом столбцов.
  4. Разложите данные по справочникам. Порядок важен: сначала всё, на что будут ссылаться. 
    INSERT INTO category (category_name)
SELECT DISTINCT TRIM(category_name) FROM staging_product WHERE category_name IS NOT NULL;

INSERT INTO manufacturer (manufacturer_name)
SELECT DISTINCT TRIM(manufacturer_name) FROM staging_product WHERE manufacturer_name IS NOT NULL;

INSERT INTO product (product_name, description, composition, price, image_file, category_id, manufacturer_id)
SELECT TRIM(s.product_name), s.description, s.composition, REPLACE(s.price, ',', '.')::NUMERIC,
       NULLIF(TRIM(s.image_file), ''), c.category_id, m.manufacturer_id
FROM staging_product s
JOIN category c ON c.category_name = TRIM(s.category_name)
JOIN manufacturer m ON m.manufacturer_name = TRIM(s.manufacturer_name);
    • DISTINCT — убрать дубли; TRIM — убрать пробелы по краям.
    • REPLACE(price, ',', '.')::NUMERIC — заменить запятую на точку и превратить текст в число.
    • NULLIF(x, '') — пустой текст превращает в «ничего» (NULL), чтобы программа подставила картинку-заглушку.
    • JOIN подставляет вместо названия категории её номер.
  5. Последовательность загрузки: роли → категории и производители → пользователи → товары → размеры/остатки → заказы → состав заказов. Заказы нельзя загрузить раньше товаров.
  6. Проверьте количество строк. 
    SELECT 'product' AS table_name, COUNT(*) FROM product
UNION ALL SELECT 'app_user', COUNT(*) FROM app_user
UNION ALL SELECT 'customer_order', COUNT(*) FROM customer_order;
    Сравните с числом строк в Excel. Не совпало — ищите, какие строки потерялись (чаще всего из-за пробелов или разных написаний названий в JOIN).

7.3. Поиск, фильтр, сортировка — в реальном времени

Секрет совместной работы: одна функция получает сразу все три параметра. Любое изменение любого поля заново вызывает её и перерисовывает список. Поэтому сортировка не «слетает» при поиске, а фильтр дружит с поиском.

for variable in (self.search_var, self.category_var, self.sort_var):
    variable.trace_add("write", self.render)      # любое изменение → перерисовка

trace_add("write", ...) означает «вызывай функцию каждый раз, когда значение переменной меняется». Кнопки «Найти» нет — всё происходит в момент ввода каждой буквы.

Сама логика в rules.filter_and_sort (см. выше): пропускаем товар, если его категория не совпала с выбранной (кроме «Все категории»); пропускаем, если строка поиска не найдена ни в названии, ни в описании (.lower() — чтобы регистр не мешал); потом сортируем по цене со скидкой.   2. для каждой позиции списать остаток: UPDATE ... SET quantity = quantity - N ... AND quantity >= N. Если строка не обновилась (rowcount == 0), значит остатка не хватило — выбрасываем ошибку, и вся транзакция откатывается;
  3. записать позицию в order_item.

После успеха корзина очищается, app.back() возвращает в каталог, а refresh() перечитывает данные — остатки пересчитаны, подсветка и «много/мало» обновились.

8.1. Список заказов

Таблица ttk.Treeview с двумя столбцами: дата и ФИО. Идентификатор заказа хранится в iid строки — его не видно, но по нему мы знаем, какой заказ выбран. Двойной клик открывает состав.

8.2. Добавление заказа

Задание требует: товары выбираются из каталога с поиском по названию → форма товара → размер и количество. Мы используем уже готовый каталог: кнопка «Добавить заказ» открывает его, позиции собираются в корзину, а на странице корзины менеджер выбирает клиента (load_customers) и подтверждает. Ничего писать заново не пришлось — это и есть польза от того, что страницы устроены как конструктор.

8.3. Состав заказа и сумма

Для каждой позиции показываются: товар (наименование + производитель), размер, количество, цена за единицу, сумма по строке. Внизу итог: rules.calc_order_total складывает «цена × количество» по всем строкам. Обратите внимание на sum(..., Decimal("0")): начинаем сложение с «денежного» нуля.

8.4. Удаление и редактирование (только администратор)

  • Изменить дату: текст разбирается через datetime.strptime(текст, "%d.%m.%Y"). Если введено «31.02.2026» — сработает ValueError, и пользователь увидит окно с примером правильной даты.
  • Удалить позицию или заказ: перед удалением — вопрос askyesno (предупреждение о необратимом действии). В транзакции сначала возвращаем товар в остаток (UPDATE ... SET quantity = quantity + ...), потом удаляем строки.
  • После любого изменения вызывается refresh(), и таблица обновляется.
Задание допускает разные трактовки слова «позиции». Если вам непонятно, что именно нужно (удалять заказ целиком или строки внутри заказа), задайте вопрос эксперту по формулировке — это разрешено, ответ дадут всем. В примере реализованы оба варианта.

Урок 9. Как переделать пример под свой вариант

На экзамене предметная область будет другой: не обувь, а, скажем, мебель, книги, бытовая техника. Принцип тот же — меняются названия. Алгоритм переделки:

  1. Найдите в Приложении 1 «главный объект» (товар/модель) и его «ключевой параметр» (в обуви — размер; в другой области может называться иначе). Остаток хранится на пару «объект + параметр».
  2. Составьте таблицу соответствия: product → ваш объект, size_value → ваш параметр, customer_order → ваш заказ.
  3. В schema.sql замените названия и поля на свои.
  4. В database.py поправьте SQL: поля в SELECT и названия таблиц.
  5. В catalog_page.py поменяйте поля, которые показываете в карточке, на те, что в макете вашего задания.
  6. Условия скидки и подсветки (проценты, пороги) бывают другими — они лежат в самом верху rules.py: DISCOUNT_RATE, MANY_PAIRS_LIMIT, LOW_STOCK_LIMIT. Прочтите условие внимательно: «больше» или «не меньше», «предыдущий месяц» или «последние 30 дней».
  7. Из style.py уберите мои цвета и впишите цвета и шрифты из вашего Приложения 3.
Хорошая тренировка: возьмите другую предметную область (книжный магазин, автозапчасти), придумайте схему и переделайте проект за два часа. После этого экзамен перестанет быть страшным.

Урок 10. Git: как сдать работу

Все результаты сдаются загрузкой файлов в репозиторий. Загружать нужно по ходу каждого задания, а не в последнюю минуту.

Что понадобится один раз

git config --global user.name "Иван Иванов"
git config --global user.email "ivan@example.com"
git clone АДРЕС_РЕПОЗИТОРИЯ

Адрес репозитория и логин/пароль выдаёт технический эксперт. Команда clone создаёт на компьютере папку-копию репозитория — работайте внутри неё.

Три команды, которые вы будете повторять

git add .
git commit -m "Задание 1: база данных, скрипт и ER-диаграмма"
git push
  • git add . — «отметить все изменённые файлы к сохранению».
  • git commit -m "..." — сохранить «снимок» с пояснением.
  • git push — отправить снимок на сервер. Только после этого эксперт увидит работу.

Проверка: git status должен писать «nothing to commit, working tree clean».

Что должно лежать в репозитории

репозиторий/
├── README.md              ← описание функциональности
├── src/ (или app/)        ← исходный код: папки и файлы, НЕ архив
├── db/
│   ├── db_script.sql      ← структура + данные
│   └── er_diagram.pdf     ← ER-диаграмма
├── bin/ (или dist/)       ← исполняемые файлы
└── resources/             ← картинки, логотип, иконка

Исходный код загружают именно структурой файлов, а не архивом — .zip или .rar вместо папки считается ошибкой.

Исполняемый файл для Python

Если на рабочем месте есть pyinstaller, получить .exe можно так:

pip install pyinstaller
pyinstaller --onefile --windowed --add-data "resources;resources" main.py

Готовый файл появится в папке dist. Если инструмента нет, а интернета нет — уточните у эксперта, что считать «исполняемыми файлами» для вашего стека.

README.md

Пример шаблона есть на главной странице гайда, в блоке «Сдача». Пишите конкретно: что программа умеет, как запустить, из чего состоит репозиторий. Не пишите «удобная и красивая программа» — пишите «вход по логину, каталог с поиском, оформление заказа с пересчётом остатков».

Урок 11. Что делать, когда ничего не работает

11.1. Как читать красный текст (traceback)

Когда программа падает, Python печатает цепочку вызовов. Читайте снизу вверх: последняя строка — что случилось, строка над ней — где.

Traceback (most recent call last):
  File "main.py", line 12, in <module>
    print(calc_total(items))
  File "rules.py", line 31, in calc_order_total
    return sum(item["unit_price"] * item["quantity"] for item in order_items)
KeyError: 'unit_price'

Читаем: ошибка KeyError — «в словаре нет ключа unit_price», произошла в файле rules.py на 31-й строке. Идём туда и смотрим, откуда берётся этот словарь и почему в нём нет нужного поля.

11.3. Приём «разделяй и проверяй»

  1. Не работает целое — проверьте по частям. Сначала SQL-запрос в pgAdmin: вернул ли он то, что надо?
  2. Затем функцию из database.py отдельно: добавьте внизу файла print(load_catalog()) и запустите.
  3. Затем правила: print(stock_label(5)).
  4. И только потом — окно.

print() — ваш главный инструмент отладки: выводите значения и смотрите, что на самом деле лежит в переменных.

Золотые правила

  1. Сначала работающее, потом красивое. Лучше простой рабочий каталог, чем недоделанный, но с кучей украшений.
  2. Коммитьте после каждого задания. Сбой компьютера не должен стоить вам всей работы.
  3. Не зависайте. Застряли на одном пункте больше 10 минут — оставьте заметку «TODO» и двигайтесь дальше. Вернётесь в конце.
  4. Запускайте программу после каждого небольшого изменения, а не после часа правок: иначе непонятно, что сломалось.

  6. Время на сдачу. Последние 5–10 минут — только git add / commit / push и проверка, что файлы видны в репозитории.
